    Catálogo Geral de Requisitos de Software¶

    Este capítulo consolida o Catálogo Geral de Requisitos de Software do sistema DUOC Finance, unificando a especificação detalhada dos Requisitos Funcionais (RF01 a RF40), das Regras de Negócio (RN01 a RN31) e dos Requisitos Não Funcionais (RNF01 a RNF20) em torno dos quatro Objetivos Específicos (OE) e suas respectivas Características (CAR), definidas na Solução Proposta.

    Todos os elementos estão interligados por vínculos bidirecionais navegáveis: ao consultar um Requisito Funcional, é possível transicionar diretamente para suas Regras de Negócio e Requisitos Não Funcionais condicionantes e, a partir de qualquer regra ou métrica, retornar imediatamente aos requisitos que a executam.

    Utilize a barra de pesquisa e os filtros rápidos abaixo para navegar dinamicamente entre os 91 Itens Estruturantes do catálogo (40 Requisitos Funcionais, 31 Regras de Negócio e 20 Requisitos Não Funcionais). Cada card consolida a especificação oficial, critérios de aceitação DoR/DoD e rastreabilidade direta com os elementos estruturantes do projeto como # OEs ↗, # CARs ↗, # Matriz 4 × 4 ↗, # Governança & CLT/LGPD ↗, # RNs ↗ e # RNFs ↗.

    RF01 - Cadastrar colaborador
    História de Usuário (US01)

    Como Administrador Financeiro, quero cadastrar um novo colaborador com seus dados pessoais, bancários e trabalhistas, para que exista uma base única e validada por CPF que sustente os apontamentos e os pagamentos de diárias.

    Critérios Oficiais e Processo de Verificação (DoR / DoD) 3 de 3 Validados (Incr. 1)
    Critério Funcional Oficial (Verificável)

    O Administrador Financeiro (ADMIN_FINANCEIRO) cadastra um novo profissional informando seus dados cadastrais, bancários (código de compensação COMPE de 3 dígitos, agência e conta corrente) e trabalhistas validados (RN01, RN03, RN22), e o sistema grava o registro com um identificador único. Se for concedido acesso ao sistema, é gerado e despachado um link seguro de primeiro acesso e ativação para o e-mail corporativo cadastrado (RF17), permitindo definir senha para autenticação subsequente (RF13). Se o CPF informado for inválido segundo o algoritmo oficial da Receita Federal (módulo 11) ou já constar na base de dados, o cadastro é recusado e nenhum registro novo é criado (RN01).
